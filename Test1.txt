# Python ETL Engine — Implementation Plan

Build a production-grade, config-driven Python ETL engine in the existing `backend/` directory that supports multi-source extraction, Excel-driven transformations, truncate-and-load, CDC Type 2 (SCD2), concurrency, chunking, and parallelism.

## User Review Required

> [!IMPORTANT]
> **Database Drivers**: The engine will import `cx_Oracle` and `teradatasql` but will not fail at startup if they are not installed — connections will raise clear errors at runtime. This avoids forcing every developer to install vendor-specific drivers.

> [!IMPORTANT]
> **No PySpark**: This engine replaces the previous PySpark-based backend with a pure pandas + dask stack. SQLAlchemy handles all DB I/O. If you still need PySpark support, let me know.

> [!WARNING]
> **CDC Type 2 in-memory**: The SCD2 comparison is done in-memory (pandas merge). For extremely large existing tables (100M+ rows) this will require significant RAM. Chunked CDC is planned but initial implementation will handle the full target table for comparison.

#### [NEW] [cdc_type2_loader.py](file:///Users/pavankumarvarakudujayaram/Desktop/Code/Config-Python-AI-App/backend/loaders/cdc_type2_loader.py)

SCD Type 2 logic:
1. Read existing active records (`is_current = 1` or `end_date IS NULL`)
2. Merge incoming data on natural key columns
3. **New rows** → Insert with `effective_date = now`, `end_date = NULL`, `is_current = 1`
4. **Changed rows** → Close old record (`end_date = now`, `is_current = 0`), insert new version
5. **Unchanged rows** → No action
6. Comparison is via a hash of tracked columns (MD5)

### Pipeline Scenarios (★ New)

Each pipeline type lives in its own module under `pipelines/`. `main.py` reads `pipeline_type` from the JSON config and dispatches to the corresponding module.

#### [NEW] [file_to_file.py](file:///Users/pavankumarvarakudujayaram/Desktop/Code/Config-Python-AI-App/backend/pipelines/file_to_file.py)

**FILE → FILE** pipeline:
1. Extract from source file (CSV/Excel/Parquet/JSON/TXT) using `FileExtractor`
2. Apply transformations via `PandasTransformer`
3. Write to target file via `FileLoader`
4. Supports chunked processing for large files

#### [NEW] [file_to_db.py](file:///Users/pavankumarvarakudujayaram/Desktop/Code/Config-Python-AI-App/backend/pipelines/file_to_db.py)

**FILE → DB** pipeline:
1. Extract from source file using `FileExtractor`
2. Apply transformations via `PandasTransformer`
3. Load to DB using either `TruncateLoader` or `CDCType2Loader` based on `load_strategy` in config
4. Supports chunked insert for large files

#### [NEW] [db_to_db.py](file:///Users/pavankumarvarakudujayaram/Desktop/Code/Config-Python-AI-App/backend/pipelines/db_to_db.py)

**DB → DB** pipeline:
1. Extract from source DB using `DBExtractor` (query or table scan)
2. Apply transformations via `PandasTransformer`
3. Load to target DB using either `TruncateLoader` or `CDCType2Loader`
4. Source and target can be different DB types (Oracle → Teradata, etc.)

#### [NEW] [db_to_file.py](file:///Users/pavankumarvarakudujayaram/Desktop/Code/Config-Python-AI-App/backend/pipelines/db_to_file.py)

**DB → FILE** pipeline:
1. Extract from source DB using `DBExtractor`
2. Apply transformations via `PandasTransformer`
3. Write to target file via `FileLoader`
4. Supports chunked export for large result sets

#### Dispatch logic in `main.py`

```python
PIPELINE_REGISTRY = {
    "FILE_TO_FILE": file_to_file.run,
    "FILE_TO_DB":   file_to_db.run,
    "DB_TO_DB":     db_to_db.run,
    "DB_TO_FILE":   db_to_file.run,
}

def main(config_path):
    config = load_config(config_path)
    runner = PIPELINE_REGISTRY[config.pipeline_type]
    for table_cfg in config.tables:
        runner(table_cfg, monitor)
```
