# PySpark ETL Standalone Runner

This package allows running ETL pipelines **without the Flask/React stack**, directly from the command line or via **Autosys job scheduling**.

## Quick Start

```bash
# From the project root directory:
python standalone/run_pipeline.py \
    --config  backend/config/CSV_TO_CSV.json \
    --params  backend/parameterfile.txt \
    --env-file .env
```

## Directory Layout

```
pyspark_app/
├── standalone/              ← YOU ARE HERE (deploy this + backend/)
│   ├── run_pipeline.py      # CLI entry point
│   ├── run_pipeline.sh      # Shell wrapper for Autosys
│   ├── requirements.txt     # Minimal Python dependencies
│   └── README.md            # This file
│
├── backend/                 ← Required (ETL engine + modules)
│   ├── etl_engine.py        # Core engine (Factory pattern)
│   ├── file_to_file_etl.py  # FILE → FILE pipeline
│   ├── file_to_db_etl.py    # FILE → DB pipeline
│   ├── db_to_file_etl.py    # DB → FILE pipeline
│   ├── db_to_db_etl.py      # DB → DB pipeline
│   ├── transformations.py   # Transformation engine
│   ├── sources.py           # Source readers (File, DB)
│   ├── targets.py           # Target writers (File, DB)
│   ├── audit_logger.py      # Audit metrics
│   ├── reject_handler.py    # Reject row handling
│   └── jars/                # JDBC driver JARs
│
└── .env                     ← Database credentials (optional)
```

## CLI Arguments

| Argument | Short | Required | Description |
|----------|-------|----------|-------------|
| `--config` | `-c` | **Yes** | Path to JSON pipeline configuration file |
| `--params` | `-p` | No | Path to `parameterfile.txt` for environment overrides |
| `--env-file` | `-e` | No | Path to `.env` file with DB credentials |
| `--log-dir` | `-l` | No | Directory for execution log files |

## Exit Codes

| Code | Meaning | Autosys Status |
|------|---------|----------------|
| `0` | Pipeline completed successfully | SUCCESS |
| `1` | Pipeline execution failed (runtime error) | FAILURE |
| `2` | Bad arguments, missing files, or invalid config | FAILURE |

## Autosys Integration

### JIL Definition Example

```jil
/* ============================================ */
/*  Daily ETL Load Job                          */
/* ============================================ */

insert_job: ETL_DAILY_LOAD
job_type: CMD
command: /opt/etl/standalone/run_pipeline.sh \
    --config /opt/etl/configs/daily_load.json \
    --params /opt/etl/parameterfile.txt \
    --env-file /opt/etl/.env \
    --log-dir /opt/etl/logs
machine: etl-server-01
owner: etl_user
permission: gx,ge
date_conditions: 1
days_of_week: mo,tu,we,th,fr
start_times: "06:00"
std_out_file: /opt/etl/logs/autosys_stdout.log
std_err_file: /opt/etl/logs/autosys_stderr.log
alarm_if_fail: 1
max_run_alarm: 120   /* Alert if job runs > 2 hours */
```

### Chained Jobs Example

```jil
/* Job 1: Extract stage */
insert_job: ETL_EXTRACT_STAGE
job_type: CMD
command: /opt/etl/standalone/run_pipeline.sh --config /opt/etl/configs/extract.json
machine: etl-server-01
owner: etl_user

/* Job 2: Transform & Load (depends on extract) */
insert_job: ETL_TRANSFORM_LOAD
job_type: CMD
command: /opt/etl/standalone/run_pipeline.sh --config /opt/etl/configs/transform_load.json
machine: etl-server-01
owner: etl_user
condition: success(ETL_EXTRACT_STAGE)
```

## Parameter File Format

The `parameterfile.txt` injects environment-specific values into the JSON config at runtime:

```
# Lines starting with # are ignored
AUDIT_PATH=/opt/etl/logs/audit
REJECT_PATH=/opt/etl/logs/reject
SPARK_JARS=/opt/etl/jars/ojdbc8.jar,/opt/etl/jars/postgresql-42.7.3.jar
```

These override the corresponding values in the JSON config, allowing the **same JSON config** to run in different environments (dev, staging, prod) just by swapping the parameter file.

## JSON Configuration Structure

```json
{
  "pipeline": {
    "pipeline_id": "MY_PIPELINE",
    "pipeline_type": "FILE_TO_FILE",   // FILE_TO_FILE | FILE_TO_DB | DB_TO_FILE | DB_TO_DB
    "execution_mode": "BATCH",
    "log_level": "INFO"
  },
  "source": {
    "type": "FILE",                    // FILE or DB
    "format": "csv",
    "path": "/data/input/file.csv",
    "options": { "header": true, "delimiter": "," }
  },
  "target": {
    "type": "FILE",
    "format": "csv",
    "path": "/data/output/result.csv",
    "mode": "overwrite",
    "options": { "header": true }
  },
  "transformations": [...],
  "field_mappings": [...],
  "audit": { "enable": true, "path": "/logs/audit" },
  "reject": { "enable": true, "path": "/logs/reject" }
}
```

## Deployment Steps

1. **Copy files** to the production server:
   ```bash
   rsync -av standalone/ backend/ .env etl-server:/opt/etl/
   ```

2. **Install Python dependencies** (Python 3.8+ required):
   ```bash
   pip install -r /opt/etl/standalone/requirements.txt
   ```

3. **Make the shell script executable**:
   ```bash
   chmod +x /opt/etl/standalone/run_pipeline.sh
   ```

4. **Test manually** before scheduling:
   ```bash
   /opt/etl/standalone/run_pipeline.sh \
       --config /opt/etl/configs/my_pipeline.json \
       --params /opt/etl/parameterfile.txt
   echo "Exit code: $?"
   ```

5. **Submit Autosys JIL** once manual test passes:
   ```bash
   jil < /opt/etl/autosys/my_pipeline.jil
   ```

## Troubleshooting

| Issue | Solution |
|-------|----------|
| `ModuleNotFoundError: No module named 'etl_engine'` | Ensure `PYTHONPATH` includes the `backend/` directory. The shell wrapper handles this automatically. |
| Exit code `2` with validation errors | Check that your JSON has `pipeline`, `source`, and `target` blocks |
| `ClassNotFoundException: oracle.jdbc.OracleDriver` | Ensure JDBC JARs are in `parameterfile.txt` under `SPARK_JARS` |
| Audit files not generated | Verify `audit.enable: true` in JSON and `AUDIT_PATH` in parameterfile.txt |
